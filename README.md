## 1. პროექტის შესახებ (About the Project)

**MediBook** არის თანამედროვე, მინიმალისტური HealthTech პლატფორმა პაციენტების მიერ ექიმების მარტივი მოძიებისა და სამედიცინო ვიზიტების კომფორტული დაჯავშნისთვის (*Minimalist HealthTech platform for patient appointment booking and doctor discovery*).

პლატფორმა შექმნილია პაციენტისა და კლინიკის საჭიროებების გათვალისწინებით: მომხმარებელს შეუძლია რეალურ დროში გაფილტროს ექიმები სპეციალობების მიხედვით, მოიძიოს სასურველი სპეციალისტი სახელის, კლინიკის ან ლოკაციის მიხედვით, გაეცნოს ექიმის პროფილს, გამოცდილებასა და რეიტინგს, შეარჩიოს ხელსაყრელი დროის სლოტი და უსაფრთხოდ დაადასტუროს ვიზიტი.

## 2. ძირითადი ფუნქციონალი (Key Features)

- 🔍 **ოპტიმიზებული ძიება (Debounced Search - `useDebounce` 300ms):**  
  საძიებო ველში ინტეგრირებულია `useDebounce` Custom Hook-ი 300ms ოპტიმიზებული დაყოვნებით, რაც გამორიცხავს ყოველ სიმბოლოზე არასაჭირო გამოთვლებსა და გადარენდერებას. ძიება ხორციელდება ექიმის სახელის, სპეციალობის, კლინიკისა და ლოკაციის მიხედვით.

- 🩺 **სპეციალობის მიხედვით ფილტრაცია (Specialty Filtering):**  
  მყისიერი ფილტრაცია კატეგორიების მიხედვით (კარდიოლოგი, ნევროლოგი, პედიატრი, ენდოკრინოლოგი, თერაპევტი, ორთოპედი, ოფთალმოლოგი, დერმატოლოგი, გასტროენტეროლოგი) `useMemo` ჰუკის დახმარებით.

- 🪟 **მოდალური ფანჯარა (React Portals Modal with ESC/Backdrop Close):**  
  მოდალური დიალოგი რეალიზებულია `createPortal`-ის გამოყენებით უშუალოდ `document.body`-ზე, რაც გამორიცხავს მშობელი კომპონენტების `z-index`-ისა და `overflow`-ს კონფლიქტებს. მოდალი იხურება როგორც `Escape` კლავიშით, ისე Backdrop-ზე დაკლიკებით და ავტომატურად ბლოკავს ფონის სქროლვას (`overflow: hidden`).

- 📝 **ფორმის ვალიდაცია და ორმაგი გაგზავნის ბლოკირება (Form Validation with Double-Submission Lock):**  
  ჯავშნის ფორმა (`BookingForm`) ამოწმებს ყველა სავალდებულო ველს (პაციენტის სახელი, მოქმედი ტელეფონის ნომერი, თარიღი და ხელმისაწვდომი საათი). `isSubmitting` მდგომარეობის მეშვეობით ხდება ღილაკის მყისიერი დაბლოკვა, რაც სრულად აცილებს თავიდან განმეორებით გაგზავნასა და დუბლირებულ ჯავშნებს (Double-Submission Lock).

- 💾 **მონაცემთა ლოკალური შენახვა (LocalStorage Persistence):**  
  ყველა დადასტურებული ჯავშანი (`medibook_appointments`) და მომხმარებლის პროფილი (`medibook_user`) ინახება ბრაუზერის `localStorage`-ში. მონაცემები სრულად ნარჩუნდება გვერდის გადატვირთვის შემდეგაც და უზრუნველყოფილია ჯავშნების სრული მართვა (შექმნა, დათვალიერება, გაუქმება და წაშლა).

- 🛡️ **შეცდომების დამუშავება (ErrorBoundary):**  
  კლასობრივი React კომპონენტი (`ErrorBoundary`), რომელიც იჭერს რენდერის პროცესში წარმოქმნილ გაუთვალისწინებელ JavaScript შეცდომებს (`componentDidCatch`, `getDerivedStateFromError`) და მომხმარებელს აწვდის ესთეტიკურ Fallback ინტერფეისს გვერდის განახლების ოფციით.

## 5. ინსტალაცია და ლოკალური გაშვება (Installation & Local Setup)

### წინაპირობები (Prerequisites)
- **Node.js**: ვერსია `20.x` ან უფრო ახალი (Node.js 20+)
- **npm** (მოყვება Node.js-ს) ან ალტერნატიული პაკეტ მენეჯერი

### გაშვების ნაბიჯები

1. **რეპოზიტორიის კლონირება (Git Clone):**
   ```bash
   git clone https://github.com/neekall/medibook.git
   cd medibook
   ```

2. **დამოკიდებულებების ინსტალაცია (npm install):**
   ```bash
   npm install
   ```

3. **დეველოპმენტ სერვერის გაშვება (npm run dev):**
   ```bash
   npm run dev
   ```
   აპლიკაცია ხელმისაწვდომი იქნება მისამართზე: `http://localhost:5173`

## 7. ტექნიკური ანგარიში და არქიტექტურა (Technical Report & Architecture)

### 7.1 არქიტექტურული პრინციპები (No False Claims)
პროექტი აგებულია სუფთა, დეკლარაციული React არქიტექტურით. არ არის გამოყენებული არცერთი ყალბი ან არარსებული backend ბიბლიოთეკა (*No False Claims*) — მთელი ბიზნეს ლოგიკა, მონაცემთა მოდელირება და მდგომარეობის მართვა ეყრდნობა React 19-ის, TypeScript-ისა და Web API-ების სტანდარტულ შესაძლებლობებს.

### 7.2 კომპონენტური იზოლაცია და React Portals
მოდალური ფანჯრისთვის გამოყენებულია `ReactDOM.createPortal(..., document.body)`. ეს უზრუნველყოფს DOM ხეში კომპონენტის იზოლირებას ძირითადი კონტეინერებისგან, რაც თავიდან აცილებს `z-index`-ის ფენების კონფლიქტს და `overflow: hidden` შეზღუდვებს. მოდალში გაწერილია კლავიატურის მოვლენები (`keydown` -> `Escape`), ფონური დაჭერის დამმუშავებელი (Backdrop Click) და `document.body.style.overflow = 'hidden'` სქროლის დაბლოკვისთვის.

### 7.3 წარმადობის ოპტიმიზაცია (Performance Optimization)
1. **Debouncing (`useDebounce` 300ms):** საძიებო ინპუტზე ყოველ სიმბოლოზე ძებნის შესრულების ნაცვლად, შექმნილია მორგებული ჰუკი `useDebounce`, რომელიც აყოვნებს მნიშვნელობის განახლებას 300 მილიწამით.
2. **მემოიზაცია (`useMemo`):** ექიმების სია იფილტრება `useMemo`-ს შიგნით საძიებო ფრაზისა და შერჩეული სპეციალობის მიხედვით, რაც გამორიცხავს ხელახალ ფილტრაციას არაარსებითი გადარენდერების დროს.

### 7.4 ფორმის ვალიდაცია და უსაფრთხოება
`BookingForm` იყენებს კონტროლირებად ინპუტებს (Controlled Components) და Client-Side ვალიდაციის მექანიზმს:
- პაციენტის სახელის სისრულის შემოწმება.
- ტელეფონის ნომრის ფორმატის ვალიდაცია (მინიმუმ 8 სიმბოლო).
- თარიღისა და ხელმისაწვდომი დროის სლოტის სავალდებულო ვალიდაცია.
- **Double-Submission Lock:** ფორმის გაგზავნისას აქტიურდება `isSubmitting = true`, რაც თიშავს (`disabled`) გაგზავნის ღილაკს და ხელს უშლის მომხმარებლის მიერ განმეორებით დაკლიკებასა და დუბლირებული ჯავშნის შექმნას.

### 7.5 მონაცემთა შენარჩუნება (LocalStorage Persistence)
ჯავშნები ინახება ბრაუზერის `localStorage`-ში გასაღებით `medibook_appointments`. აპლიკაციის ჩატვირთვისას ხდება უსაფრთხო `try/catch` წაკითხვა, ხოლო ნებისმიერი ცვლილებისას (ახალი ჯავშანი, გაუქმება/წაშლა) — ავტომატური სინქრონიზაცია `useEffect`-ით.

### 7.6 მდგრადობა და Fault Tolerance (`ErrorBoundary`)
აპლიკაციის ძირითადი ხე შეფუთულია კლასობრივი `ErrorBoundary` კომპონენტით. თუ რომელიმე ქვეკომპონენტში მოხდება გაუთვალისწინებელი შეცდომა, აპლიკაცია არ წყვეტს მუშაობას თეთრი ეკრანით (*White Screen of Death*), არამედ აჩვენებს ინფორმაციულ შეტყობინებას მომხმარებლისთვის და გვერდის განახლების ღილაკს.
